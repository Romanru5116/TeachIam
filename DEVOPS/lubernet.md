Команда kubectl get nodes в Kubernetes используется для получения списка всех рабочих машин (узлов/nodes), входящих в кластер. Она показывает состояние, версию Kubernetes, возраст узла и роль (master/worker), позволяя администратору быстро проверить работоспособность инфраструктуры, доступность машин и возможность размещения на них подов. 
Основные элементы вывода:
NAME: Имя узла.
STATUS: Текущее состояние (обычно Ready, если узел исправен).
ROLES: Роль узла (например, control-plane или worker).
AGE: Время, прошедшее с момента создания узла.
VERSION: Версия Kubelet, работающая на узле. 
Полезные связанные команды:
kubectl get nodes -o wide — показывает больше информации (в т.ч. IP-адреса и операционную систему).
kubectl describe node <имя-ноды> — отображает подробную информацию о конкретном узле.
kubectl top node — выводит информацию о потреблении ресурсов (CPU/RAM).

Работа с профилями Minikube
Minikube позволяет создавать несколько независимых кластеров и переключаться между ними.

По умолчанию, когда запускаем командой$minikube start, Minikube создает один локальный кластер с настройками по умолчанию.

Но бывает, что тебе нужно несколько разных кластеров на одном компьютере, например:

один для экспериментов;

второй для тестирования другого приложения;

третий — чтобы повторить и воспроизвести чужую ошибку.

И вот здесь появляются профили, — profiles. Каждый профиль — это полностью отдельный Kubernetes-кластер:

свой набор подов;

свои сервисы;

свои ingress’ы;

свои настройки ресурсов;

свой IP и сеть.

Профили не конфликтуют между собой.

Запустим кластер с именем профиля Num1 и Num2 командами:

minikube start --driver=docker -p Num1
minikube start --driver=docker -p Num2
