1 Предназначен для зпуска виртуализации на 1 хосте Minikube — это инструмент для запуска одноузлового (локального) кластера Kubernetes на персональном компьютере, предназначенный для разработки, тестирования и обучения.
Он позволяет создавать, тестировать и отлаживать контейнерные приложения без необходимости развертывания полноценной облачной инфраструктуры. Minikube поддерживает работу через Docker, VirtualBox, KVM и другие гипервизоры. 
2 Компоненты:Основные компоненты Minikube:
CLI-инструмент (minikube):
-Командная строка для управления кластером (start, stop, delete, status).
Драйвер виртуализации: Механизм, создающий изоляцию. Поддерживаются Docker, Podman, VirtualBox, VMware, KVM2, Hyper-V.
Виртуальная машина (узел): Одноузловая ОС (обычно Linux), работающая как мастер-нод и воркер-нод одновременно. 
-Компоненты кластера Kubernetes внутри Minikube:
kubelet: Агент, обеспечивающий работу подов.
kube-apiserver: Точка входа для взаимодействия с кластером через {Link: kubectl https://kubernetes.io/ru/docs/tutorials/hello-minikube/}.
etcd: Хранилище конфигураций кластера.
Container Runtime: Среда выполнения контейнеров, такая как Docker или containerd.
CNI (Container Network Interface): Сетевой плагин для взаимодействия подов. 
Minikube также включает встроенные аддоны (DNS, Dashboard, Ingress) для расширения функциональности. 
3 Возможности
4 УПравление: Основные способы конфигурации Minikube:
Настройка при старте (рекомендуется): Используйте флаги для настройки ресурсов и драйвера.
Пример: minikube start --cpus 4 --memory 8192 --driver=docker.
Использование аддонов: Включение функциональности (Ingress, Dashboard, Metrics Server).
minikube addons enable ingress.
Установка произвольных параметров: Применение флага --extra-config для настройки компонентов (kubelet, apiserver).
Пример: minikube start --extra-config=kubelet.cgroup-driver=systemd.
Изменение постоянных настроек:
minikube config set <key> <value> (например, minikube config set driver kvm2).
Работа с несколькими кластерами:
Использование --profile для создания и настройки отдельных сред. 
Конфигурация по умолчанию сохраняется в ~/.minikube/config/config.jso
