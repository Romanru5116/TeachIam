Основные команды
Основные режимы запуска Docker Compose включают фоновый режим (-d), интерактивный режим (по умолчанию, без флагов) и запуск с пересборкой образов (--build). Используйте docker-compose up -d для отсоединения от терминала и постоянной работы, а docker-compose stop/down для остановки. 
Основные команды запуска
Фоновый режим (-d или --detach): docker-compose up -d. Запускает контейнеры в фоне, освобождая терминал.
Интерактивный режим (по умолчанию): docker-compose up. Логи всех контейнеров выводятся в консоль. Остановка по Ctrl+C остановит все контейнеры.
Принудительная пересборка (--build): docker-compose up --build. Обновляет образы перед запуском, полезно после изменения Dockerfile.
Запуск конкретного сервиса: docker-compose up -d <имя_сервиса>. 
Политики перезапуска (в docker-compose.yml)
Определяют поведение при падении или перезагрузке демона: 
no: Не перезапускать (по умолчанию).
always: Всегда перезапускать.
on-failure: Перезапускать только при ошибке.
unless-stopped: Перезапускать всегда, кроме случаев ручной остановки.
Управление остановкой
docker-compose stop: Остановка контейнеров без удаления.
docker-compose down: Остановка и удаление контейнеров, сетей и томов. 
Терминология:
конфигурация:
Конфигурация Docker Compose описывается в YAML-файле (обычно docker-compose.yml) и состоит из нескольких ключевых разделов.
Основные разделы (Top-level elements)
services: Определение контейнеров (сервисов) вашего приложения.
networks: Настройка сетей для связи между контейнерами.
volumes: Описание хранилищ для постоянного хранения данных.
configs и secrets: Управление конфигурационными файлами и секретными данными (паролями, ключами).
version: Ранее обязательный параметр (например, '3.8'), сейчас считается устаревшим в пользу единой спецификации (Compose Specification). 
Ключевые параметры внутри services
Для каждого сервиса можно настроить:
image: Имя образа, из которого будет запущен контейнер.
build: Параметры для сборки образа из локального Dockerfile (путь к контексту, аргументы).
ports: Проброс портов между хостом и контейнером (например, "8080:80").
environment: Переменные окружения для работы приложения.
volumes: Монтирование папок или именованных томов в контейнер.
depends_on: Порядок запуска сервисов (например, веб-приложение после базы данных).
restart: Политика перезапуска контейнера (например, always или on-failure).
command: Переопределение стандартной команды запуска из образа.
networks: Список сетей, к которым должен быть подключен сервис. 


volumes (тома) в конфиграции Docker Compose — это механизм постоянного хранения данных, который позволяет сохранять файлы, создаваемые контейнером (базы данных, логи, загрузки), даже после его удаления или перезапуска. Они обеспечивают обмен данными между хост-машиной и контейнером, а также между разными контейнерами. 
Основные аспекты volumes в docker-compose.yml:
Постоянство данных: Данные, записанные в тома, не удаляются при остановке или удалении контейнера.
Два типа монтирования:
Named Volumes (Именованные тома): Управляются Docker (хранятся в /var/lib/docker/volumes/), создаются в секции volumes: верхнего уровня.
Bind Mounts (Привязка папок): Прямое отображение папки с хост-машины в контейнер (например, ./data:/var/lib/mysql).
